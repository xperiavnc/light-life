# 任务日志诊断（2.0.1）

本次修改修复的是客户端的错误展示、重复请求和余额核验，
不意味着第三方服务已经接受请求或发放奖励。

## 先确认实际运行的安装包

启动任务后第一条运行日志应包含：

```text
客户端：2.0.1(12) release / task-diag-v1
```

Debug 包会显示 `debug`。若构建时覆盖了版本号，显示对应的构建版本。
没有该标识时，先核对安装包，而不是直接假设接口已经修复。

## “失败：成功”为什么出现

旧日志只展示服务端消息，省略了业务响应码和数据类型。
消息为“成功”不代表业务响应码被接受，也不代表奖励到账。
新日志展示 `code`、`data` 的类型及 `msg`，但不展示响应数据正文。

以下是离线测试夹具，**不是用户账号的实际服务端响应**：

```text
code=9999，data=null，msg=成功
code=200，data=boolean(false)，msg=成功
```

这两种情况均不记录为成功，并停止该任务的后续重复提交。
`data=false` 不再自动解释成“服务器已记录完成”。

## 核对任务分支

日志会展示服务端任务类型及本地选中的分支，例如：

```text
taskType=0，分支=普通任务
taskType=1，分支=激励视频
```

若视频任务走了普通分支，保留这条日志用于排查。
单凭旧日志没有“展示激励广告”，尚不足以断言运行了旧包或任务类型是什么。

## 服务器要求升级

出现“版本过低，请升级APP后再使用”时，本轮停止任务提交。
本次仅调整本地 APK 的版本标识；没有更改请求签名、服务端版本头、
广告验证流程或奖励接口。更新本地 APK 的显示版本不等于解除服务端兼容限制。
应在官方客户端确认支持状态，并保留具体业务响应码。

## 积分核验

普通任务的成功响应只记作“接口已受理”，不等同于积分到账。
本轮收益以重新读取的服务器余额为准。最终余额读取失败时显示“未核验”，
不会使用旧余额伪装成已确认的 `+0`。

回归测试通过不等同于真机广告回调或真实奖励入账通过。
